# Saved BOLT30 plus frozen-VAE LOLBO continuation

Authorized launch on 2026-11-23. Reuse exactly the 30 previously measured BOLT plans for each of 200 held-out queries, then evaluate 77 batches of ten new unique plans. Endpoint: 800 total observations per task; 154,000 additional SQL evaluations campaign-wide. SQL timeout remains 50 seconds.

The variant is frozen train80-finetuned query VAE plus CPU DKL-GP/Thompson sampling and adaptive TuRBO, as in the earlier paused query continuation. It is not an end-to-end VAE retraining experiment. There is no live BOLT LLM service because warm starts are reused.

The previous canary failed because the runner strictly validated raw VAE token sequences before native execution canonicalization. The corrected path decodes to the native executed join tree, canonicalizes that tree, strictly validates the resulting plan, and checks novelty. Evidence/canonicalization_audit.json verifies this transformation on all ten accepted canary plans; all ten would have failed the old raw-token strict check. Decoder fallback is always rejected as a failed proposal. No saved plan is substituted for a new measurement. Per-latent decode seeds are preserved under bounded parallel dispatch. The bounded retry ceiling is 200 latent batches, explicitly recorded in recipe.json.

The ten-evaluation SQL canary passed, and its ten results count toward the task's 770 new-evaluation budget. The original controller runs seven private SQL workers: three on LLMOptimizer4 and four on LLMOptimizer3. Eight dedicated VAE services run on Optimizer3. The user subsequently authorized admission of an eighth worker on Optimizer3 CPUs16–19; its readiness, process and status records are under evidence/worker07 and control/extra_controller.*. Read current consolidated status to check whether it is active. The additional worker uses an independently verified private RAM database on port20437. Its separate supervisor preserves the original seven active processes and the pinned recipe/checkpoint identity. The full 200-task queue is available to the seven workers through exclusive task locks.

Progress is status.json, task progress is runs/<task>/progress.json, and durable proposal/measurement journals are runs/<task>/runtime.sqlite. Evidence/canary.json records the passed canary. Logs are logs/slot*.log. Services and SSH forwards are owned by the companion SemanticOPT campaign's process manifests. Old hybrid recovery was disabled before resource reuse.

The consolidated status command in the companion SemanticOPT README includes both the original controller pool and the additional supervised worker.
